## Starting two-minute structure

| Time | Focus | Talking point |
| --- | --- | --- |
| 0:00–0:20 | Problem and user | Who faces this problem, and what is difficult today? |
| 0:20–0:40 | Approach | What does our solution do, and why did we choose this approach? |
| 0:40–1:30 | Live demo | Follow one complete user journey and show the result. |
| 1:30–1:50 | Technical explanation | Explain React → Spring Boot → MySQL using the actual feature. |
| 1:50–2:00 | Impact and next step | State the demonstrated benefit and the most useful future improvement. |

## Demo preparation

- Write the exact click sequence and expected screen after each action.
- Prepare fictional, realistic data before presenting.
- Rehearse from a fresh starting state.
- Keep screenshots or a short recording as a backup and identify them as recorded material if used.
- Record the final demo URL and slide/recording locations in `09-submission.md`.

## Questions to prepare for

- Why this problem and target user?
- What makes the approach useful or different?
- Why did we choose this technology stack?
- How does one request travel through the application?
- How do we validate and store data?
- What works today, and what would we improve next?
- Which claims have evidence, and which are still assumptions?

## Feature explanation record

For each completed feature, add: **purpose → user action → actual source-file paths → API/data flow → visible result → limitation**.

Do not claim usage, performance, security, or impact measurements we have not verified.
