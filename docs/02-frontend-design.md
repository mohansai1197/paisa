## Our design process

1. After receiving the brief, outline the main user journey and required screens.
2. Explore two visual directions and select one.
3. Polish the opening screen: message, hierarchy, typography, color, spacing, imagery, and primary action.
4. Establish reusable styles and components, then apply them to the remaining screens.
5. Build interactions with sample data shaped like the agreed API responses.
6. Connect real API calls and add loading, empty, validation, success, and failure states.
7. Review actual browser screenshots on laptop and mobile widths; refine what we see.

## What to explain

Describe what users see first, what action they take, and how the interface guides them toward their goal. Explain how shared components keep screens consistent and how the interface responds while data loads or an action fails.
